How the skill was created

  1. Port the indicator math into TypeScript. advancedVolumeOf reads chronological OHLCV and calculates CMF(20), close-based MFI(14), volume RSI(14), the 14/28 volume oscillator, RVOL(20), daily-reset estimated CVD, and the daily VWAP proxy. The six named votes and threshold labels follow the pasted Pine logic. The tool also returns an ex-VWAP score and dated divergences. Compute module · Published indicator
  2. Wrap the math in a compute tool. advanced_volume accepts a whole price_history reference, validates daily OHLCV, and writes a structured evidence record with computed provenance and an as-of date. Registration in computeTools() makes it available to the engine. Tool adapter · Tool catalog
  3. Write the research workflow as Markdown. The skill tells the model to fetch one year of history, calculate the volume dashboard, and run the existing trend tool on the same evidence through the dashboard’s date. Two SMA entries accept periods [8,21] and [100,200]. The remaining entries use RSI(14) and MACD(12,26,9). Skill source · Trend tool
  4. Bundle the skill and declare what it needs. The built-in catalog embeds the skill. The engine reads its required-data-tools metadata and offers it when price_history is available, including a Yahoo-only setup. Adding a Markdown skill to an older release would still leave that release without the new compute tool. Built-in catalog · Skill availability

Skill frontmatter

---
name: volume-assessment
description: Assess a stock or ETF using the Advanced Volume v3.1 dashboard alongside daily price trend.
metadata:
  group: Markets
  required-data-tools: price_history
---

The Markdown body defines the research steps and attribution. The TypeScript tool defines numerical behavior, validation, and evidence. To create another assessment, use a new skill name and declare the history requirement if it can also run from the main agent with pricing alone. Add a compute tool only for calculations the existing tools cannot perform.

End-to-end sequence diagram

Read from top to bottom. SPY is the example input. Another supported ticker follows the same flow.
StepMessage flowRequest or result
1User → CLI → EngineSubmit “Assess SPY using the volume-assessment skill.” The engine offers the skill and registered tools to the model.
2Model → Skill catalog → ModelLoad the workflow. The workflow requests one daily OHLCV series and directs both computations to a shared cutoff.
3Model → Registry → Data routerRequest price_history for SPY, interval daily, period 1y. The router attempts Tauric first when configured and may try Yahoo on an eligible failure.
4Tauric → Registry → EvidenceSPY history succeeds on Tauric. The application stores dates, OHLCV, revision states, price basis, and source in a result such as e1.
5Model → Registry → Volume toolPass the whole history reference to advanced_volume. The tool excludes a same-day provisional bar, retains prior sessions flagged as subject to revision, and returns its calculation date, score, votes, and divergence events.
6Model → Registry → Trend toolPass the same history reference and set through to the dashboard date. Compute SMA, RSI, and MACD locally using the requested periods.
7Tools → Evidence → ModelRecord computed results with links to the history input. The model can optionally request bounded evidence slices or precise arithmetic.
8Model → Engine → CLIOn a completed turn, the model writes the interpretation and the engine resolves citations. In the captured SPY run, Tauric AI credits ran out after computation and before the final write-up.

Reading the dashboard

The score combines CMF, MFI, volume RSI, the volume oscillator, VWAP position, and volume versus its 20-bar average. Rising volume earns positive points even when the price is falling. RVOL, estimated CVD, and divergence readings provide context alongside the six votes. A single-day session VWAP proxy is the bar’s typical price. With daily CVD resets, the five-bar comparison measures the difference between two individual bars’ estimated deltas. A divergence becomes available on its confirmation date, five bars after the pivot with the implemented defaults. This is a descriptive assessment.

Build and verification

From the project directory with dependencies installed, run the test suite and rebuild the workspace CLI after changing TypeScript or the built-in skill catalog.

bun test
bun run typecheck
bun run build
bun scripts/compile.ts
./dist-bin/tradingagents --version

The five unit tests cover the fixed SPY scores, divergence confirmation timing, evidence references and the shared cutoff, invalid history, and built-in skill discovery with Yahoo-only pricing. The workspace executable was rebuilt and verified after local macOS signing. If macOS rejects a freshly compiled local executable because of its signature, run codesign --force --sign - dist-bin/tradingagents on the file you built.
